Critical Issues & Improvement Areas
1. Duplicate ConnectionManager Classes (Critical)
- lib/core/device_discovery_and_connection/udp_connection_request.dart:6 - UDP-based connection signaling
- lib/network/connection/connection_manager.dart:4 - TCP connection pool management
- Problem: Same name, different purposes. Causes confusion and import conflicts.
2. Incomplete Transfer Implementation
- SendTransferManager._produceChunksWithBackpressure() (lines 206-270) has TODO comments - chunks are read but never actually sent (lines 244-249 commented out)
- ReceiveTransferManager._handleMessage() (line 257) is empty
- TransferScheduler (689 lines) is fully implemented but never used - _schedulers map in SendTransferManager contains null values (line 147)
3. Missing Error Handling & Resilience
- No reconnection logic for dropped TCP connections
- No transfer resume capability (partial file transfers)
- No timeout handling for stalled transfers
- FrameParser throws StateError on malformed frames (crashes app)
4. Security Concerns
- No authentication - any device on network can connect
- Key exchange not implemented - CryptoService requires pre-shared key (where does it come from?)
- No certificate pinning or device identity verification
5. Architecture Violations
- UI directly mutates services in device_discovery_and_connection_widget.dart:74-136 - callbacks assigned in build method (side effects during render)
- UdpDiscoveryService mixes discovery, connection signaling, and device tracking (violates SRP)
- Business logic in widget callbacks (lines 182-188, 292-294)
6. Resource Management Issues
- UdpDiscoveryService creates new RawDatagramSocket per sendConnectionRequest (line 20) - socket churn
- No proper cleanup of StreamController in some classes
- TransferScheduler workers never actually send (line 407-417 commented out)
7. Testing & Observability Gaps
- No unit tests visible
- No integration tests
- Limited logging (only print() statements)
- No metrics/telemetry for transfer performance

Recommended Refactoring Plan
Phase 1: Fix Critical Bugs (Immediate)
1. Rename duplicate ConnectionManager classes:
- UdpConnectionSignaler (core/device_discovery)
- TcpConnectionManager (network/connection)
2. Complete SendTransferManager - wire up actual chunk sending via connection pool
3. Integrate TransferScheduler - replace manual chunk sending with scheduler
Phase 2: Architecture Cleanup (Short-term)
4. Extract business logic from widgets into dedicated service classes
5. Implement proper key exchange (Diffie-Hellman or QR code pairing)
6. Add connection lifecycle management (reconnect, heartbeat, timeout)
Phase 3: Robustness & Features (Medium-term)
 7. Add transfer resume (persist chunk progress to disk)
 8. Implement proper error boundaries and user-facing error messages
 9. Add unit tests for protocol parsing, crypto, transfer logic
10. Add bandwidth throttling UI and progress indicators
Phase 4: Platform & Polish (Long-term)
11. Complete platform implementations for wifi_connection plugin (Windows/Linux/macOS)
12. Add hotspot creation (not just detection)
13. Implement multi-device group transfers
